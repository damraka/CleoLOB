# v0.7 roadmap: generative market dynamics, posterior calibration, robust execution and cross-market validation

Branch `research/v0.7-generative-market-validation`, package version `0.7.0.dev0`. This is a
research branch, not a release.

## Question

> When richer generative market models, posterior calibration, parameter uncertainty,
> model-class uncertainty, regime drift, queue uncertainty, structural misspecification and
> historical counterfactual uncertainty are all accounted for, which execution conclusions
> remain scientifically defensible across time, instruments, venues and market conditions?

The progression across versions:
- v0.5 asked whether simulator conclusions survive contact with history.
- v0.6 measured how far realism error, calibration ambiguity, misspecification and regimes
  undermine them.
- v0.7 asks whether richer generators reduce those gaps, quantifies what remains, and
  certifies only the conclusions that survive simulator uncertainty. It abstains otherwise.

## Expected limits, stated in advance

- **Order-level truth.** Deribit and BitMEX Tardis samples are aggregate L2. FIFO, order
  identity, queue position, hidden liquidity and exact passive fills are `NOT_AVAILABLE` there.
  Bitstamp order-level captures are genuine but short and consumed.
- **Event resolution.** It is 100 ms for L2-derived event streams. Generators that work at the
  event level inherit this.
- **No GPU.** Neural generators and neural posterior estimation are CPU-bounded and labelled
  accordingly.
- **Compiled backends** (numba, C++, Rust) are not installed, so the accelerated path is
  vectorized numpy with differential tests.
- **Cross-platform determinism.** Linux runs in CI only when the branch is pushed. Locally only
  Windows is available.
- **Offline RL** on real data is `NOT_AVAILABLE`: no logged historical actions exist.

Every workstream will be reported in `docs/v07-requirement-coverage.md`, with its status
stated honestly.
